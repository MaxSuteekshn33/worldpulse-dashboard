Shipping layer — data sources and attribution
---------------------------------------------

LANES  (lib/lanes.ts)
  Global Shipping Lanes / Routes, v1.
  https://doi.org/10.5281/zenodo.6361763
  https://github.com/newzealandpaul/Shipping-Lanes
  Licence: Creative Commons Attribution 4.0 International (CC BY 4.0).
  Simplified here with Douglas-Peucker and rounded to two decimals; the
  geometry is otherwise unchanged. Attribution is shown in the dashboard
  footer whenever the shipping layer is on, as the licence requires.

CHOKEPOINTS  (lib/chokepoints.ts, /api/chokepoints)
  IMF PortWatch — https://portwatch.imf.org
  Public ArcGIS endpoints, no API key.
    PortWatch_chokepoints_database  — identity and position (static)
    Daily_Chokepoints_Data          — daily vessel transits (fetched live)
  Daily counts are modelled from AIS, run roughly a week behind, and are
  revised, which is why every reading is shown with the date it is for.

VESSELS  (lib/vessels.ts, /api/vessels)  — needs a key
  AISStream — https://aisstream.io — free, GitHub sign-in, key from the
  Account page. Set it as AISSTREAM_KEY in the environment; without it the
  layer simply says so and the rest of the shipping view works.

  There is no free REST feed for AIS, so this does not poll: it opens the
  WebSocket, listens for about four seconds around nine watched chokepoints,
  closes, and caches. A burst, not a stream — these are the ships that
  transmitted during the window, not every ship present.

  Constraints from AISStream's documentation that shaped it: the subscription
  must be sent within 3 seconds of connecting; 3 subscribed connections per
  account and 3 per originating IP; browser connections are refused outright,
  so it can only run server-side; slow readers have messages dropped, which
  is why the boxes are narrow rather than one box around the world.

  The alternative, if sampling proves too thin: a small always-on worker
  holding the socket permanently and writing to a store this would read.
